# External-Evidence Packaging After Technical Completion

Use when a research/engineering mission has sealed its foundation (or correction) results, later product gates remain locked, and the open risk is **outsider understanding / independent evaluation**, not more internals.

Typical Continuity Kernel / Mission Control shape:

```text
foundation: passed or honestly incomplete+corrected
T5 / memory / custom persistence / product: locked or parked
external demand: NOT ESTABLISHED
temptation: open Agent OS, T5, more isolation experiments, or claim “nobody needs this”
correct move: package sealed truth, then seek external evidence
```

## Core distinctions

| Label | Meaning | Action implication |
|---|---|---|
| `EXTERNAL_DEMAND_NOT_ESTABLISHED` | default after internal-only work | package + optional contact |
| `NO_SIGNAL_IN_SAMPLE` | bounded contact attempt, little useful response | document honestly; do not globalize |
| `RECRUITMENT_INCONCLUSIVE` | could not produce enough qualified conversations | process result, not product proof |
| `EXTERNAL_DEMAND_ABSENT` | strong global claim | requires broader honest evidence; never from a tiny sample |
| Category funding / vendor market | relevance signal only | ≠ demand for this artifact |

Also:

- technical expansion limit ≠ project worthless;
- in-repo consumer ≠ external user;
- runbook exists ≠ stranger-validated package;
- Agent OS / ambient assistant ideas may be saved as **concept only** while packaging proceeds.

## Authorized packaging scope (default)

Do:

1. Reconcile mutable entry docs to newest sealed decisions (`README`, `AGENTS`, runbook).
2. Write a ~10-minute public-safe overview (problem, what was tested, pass/fail, non-claims).
3. Write one architecture/conformance diagram + trust split.
4. List publication blockers honestly (consumer candidate gaps, doctor gaps, failpoints, privacy review, private visibility).
5. Define a clean-checkout run path with pins and host notes.
6. Update Mission Control `.active/` to name packaging-without-publication; keep T5/H1/custom persistence locked.
7. Optionally smoke doctor + sealed test packs when Docker/topology is available.

Do **not** (without a separate sealed decision):

- open T5/memory/LLM/3D/Agent OS implementation;
- flip GitHub private→public;
- start outreach campaigns;
- claim demand or consciousness;
- rewrite frozen historical artifacts in place (e.g. T2 implementation matrix);
- treat packaging as automatic consumer promotion.

## Demand / success vocabulary for the phase after packaging

Success can be any of:

- independent clean run or serious maintainer critique;
- Tier-A continuity failure case;
- employer/lab treating the artifact as credible evidence;
- honest `NO_SIGNAL_IN_SAMPLE` after a bounded contact window.

Failure is more months of internal optimization with no external contact attempt.

## Local harness ops that are packaging lessons (not “product bugs”)

When verifying Continuity Kernel-class compose harnesses:

- Doctor FAIL on connection refused usually means Docker/services down, not vector failure.
- Restate may exit with node-name mismatch against a stale volume after container ID change. For **synthetic** data, remove the Restate volume and recreate, or pin an explicit node name. Record the fix; do not weaken vectors.
- Prefer historical known-good `CK_RESTATE_DEPLOYMENT_URI` only after doctor suggests current host IPs; re-prove container→host reachability when networks change.
- Keep consumer status `CANDIDATE_ONLY` even if `example:consumer` is 5/5 green.

## Mission Control reconciliation checklist

After packaging docs land:

- `mission_mode` includes hold + packaging-docs (or equivalent), not a silent T5 unlock;
- `next_action` forbids automatic H0 rerun / H1 / T5 / public flip / outreach without review;
- research notes for future architecture (Agent OS, ambient state) stay under `references/` as concept-only with non-claims;
- implementation repo commit for packaging is separate from sealed experiment decision commits.

## Pitfalls

- Do not import a long external audit wholesale into authority; adopt/modify/reject/defer after live verification.
- Do not conclude global absence of demand from founder self-report or zero interviews.
- Do not “park H0 again” if H0 is already sealed inconclusive; leave it closed.
- Do not expand into always-on agent OS packaging language that overclaims Continuity Kernel’s current scope (commit/truth harness ≠ full agent OS).
